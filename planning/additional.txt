### 2026-09-10 채팅/LLM/Markdown 편집기 개선

현재 챗봇 채팅 화면에서 각 메시지의 입력 시간이 보이지 않아, 언제 남긴 지시와 응답인지 추적하기 어렵다. 사용자/assistant 메시지 카드에 생성 시각을 표시하고, 세션 목록의 `last_message_at` 표시와 같은 톤으로 본문 메시지에도 한국어 로컬 시간 기준의 짧은 시각 표기를 추가한다. 장시간 작업지시, 핸드오버, 재접속 이후에도 메시지 흐름을 시간순으로 확인할 수 있어야 한다.

현재 화면에 `LLM 연결 필요`가 표시되고 Gemma4 연결이 되어 있지 않은 상태다. 기본 LLM 연결 설정, 연결 테스트, 실패 시 안내 문구를 점검해 실제 채팅이 가능한 상태로 복구한다. 단순히 안내 문구만 숨기지 말고, 관리자 또는 사용자 화면에서 현재 연결 상태와 필요한 조치가 명확히 보이게 한다.

Markdown 파일 편집기가 원래 기대했던 클로드큐 MD Viewer 스타일의 WYSIWYG 편집기가 아니라, 평문 textarea 편집 + 미리보기 형태로 구현돼 있다. `/home/lisyoen/projects/md-viewer/public/src/editor.js`의 Tiptap 기반 편집기를 기준으로 APMS 문서/작업지시서 편집기에 이식한다. 요구되는 방향은 Markdown 원문을 직접 편집하는 보조 모드가 아니라, 기본 편집 경험이 MD Viewer와 같은 WYSIWYG가 되는 것이다.

이식 시 포함할 핵심 기능:
- Tiptap + `tiptap-markdown` 기반 Markdown 로드/저장
- 제목, 굵게, 기울임, 취소선, 인라인 코드, 링크, 이미지, 리스트, 체크리스트, 코드블록, 인용, 수평선, 표 삽입/편집 툴바
- `/` 입력으로 제목/리스트/체크리스트/코드블록/표 등을 넣는 slash command
- 표 우클릭 컨텍스트 메뉴
- 선택 영역 bubble menu
- ASCII 화살표(`->`, `<-`, `<->`, `=>`, `<=`) 자동 변환
- 리스트/체크리스트에서 Tab, Shift+Tab 들여쓰기/내어쓰기
- 상대 이미지 경로를 APMS의 문서/작업 파일 위치 기준으로 깨지지 않게 처리

APMS는 Next/React 구조이므로 md-viewer의 순수 DOM 초기화 코드를 그대로 복사해 붙이는 대신, 기능과 UX를 기준으로 React 컴포넌트화한다. 현재 `src/components/md/MdEditor.tsx`의 저장/취소/충돌 처리, `Ctrl/Cmd+S`, 변경사항 이탈 방지 동작은 유지하고, 본문 입력부만 WYSIWYG로 교체한다. 구현 후 기존 md editor 테스트를 WYSIWYG 기준으로 보강하고, build/test로 검증한다.
